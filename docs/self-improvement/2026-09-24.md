# RuVnet harness improvement — 2026-09-24

## Decision

Rejected the `catalog --limit 1..10` candidate and did not promote version 0.11.0. The candidate made the bounded core and MCP discovery limit available through a position-independent, fail-closed CLI option. It improved the six held-out groups from 1/6 to 6/6 and preserved the read-only authority surface, but the frozen hot-discovery p95 gate failed. The baseline remains [`e0d2b53`](https://github.com/ruvnet/ruvnet/commit/e0d2b530d25ed68a0c8bd7cf739cf04e61a95ef1).

The frozen evaluator initially required successful MCP responses to contain `isError: false`, although the optional field is omitted on success. Before scoring the candidate, that assertion was corrected to require only `isError !== true`; the [plan](2026-09-24-plan.json) preserves both runner hashes and the amendment time, and the untouched baseline still reproduced at 1/6. The original runner artifact was not retained, which limits independent diff verification. No threshold was changed after measurements.

## MetaHarness loop and measurements

The [frozen plan](2026-09-24-plan.json) defined the hypothesis, six held-out groups and thresholds before candidate work. The candidate passed 6/6 versus baseline 1/6: named limit matched the core oracle; empty-query prefixes were canonical; flag order was stable; malformed, duplicate, control, unknown and authority-shaped input failed without stdout; four official-SDK stdio sessions agreed; and default output remained unchanged. The separate regression suite, not the held-out runner, verified the unchanged six-tool and three-resource surface.

All 17 test groups and the manifest validator passed on Node 22 and 24. Both marketplace schemas, four skills, six MCP tools and three resources remained valid. MetaHarness 0.4.16 retained 6/6 hard constraints and 3/4 soft constraints; that heuristic score is not proof of improvement. The package contained 18 files, compressed to 31,235 bytes, and its normalized 94-entry dependency closure was byte-identical to baseline.

Fifteen alternating pairs used 10,000 hot exact-discovery calls and 20 equivalent-output cold CLI starts per arm per pair. Seed 1729 is metadata only: the runner uses fixed alternating order and no RNG. Median hot p95 rose from 0.000891 ms to 0.001101 ms: +23.569%, +0.000210 ms. The frozen rule required both at most +20% relative and +0.05 ms absolute, so this failed despite the tiny absolute change. Cold p95 improved 2.415% to 70.286753 ms; RSS increased 241,664 bytes. [Raw paired measurements](2026-09-24-benchmarks.json) retain every run. The benchmark was bound to a labeled local worktree rather than an exact candidate commit, an additional reproducibility limitation.

Pinned Ruflo 3.25.6 code, dependency, secret and STRIDE scans plus npm audit reported zero known high or critical findings. Secret scanning covered only five files and STRIDE only four, so coverage is limited; this is not a complete-security claim.

Independent review also rejected promotion because the frozen conjunctive latency rule failed and could not be reinterpreted after measurement. No candidate branch or code was pushed, no source change reached `main`, and no candidate CI was requested after the frozen local gate rejected it. The report-only update was validated separately.

## ruOS, memory and learning

ruOS remains **INCONCLUSIVE**. All ten desktops had null heartbeat; the nominal evaluation desktop was provisioned but never proved live or isolated. This CLI-only parser candidate did not affect a desktop journey, MCP UI, OAuth or graphical control, so the frozen policy did not require a live probe. No command or screenshot request was issued. The trusted Dream Machine verifier at `aa931ca` passed 59/59 offline tests, which establishes neither a live tenant nor authoritative completion or pixels.

The sanitized corpus would contain 11 catalog projects plus 54 reviewed changes, or 65 records, still below the frozen 100-record vector/GNN gate. Exact retrieval remains the shipped baseline. Product RuVector retrieval, WASM acceleration, GNN training and persistent autonomous learning remain unimplemented and unclaimed. No coordination-memory pattern was stored because the candidate failed its acceptance gate.

## Forecast

Prediction, 84% confidence by 2026-12-23: agent and MCP promotion suites will add a version-evolution compatibility lane using historical or deterministically mutated tool schemas and report compatibility regression separately from pinned-version success. It passes only if at least two primary benchmark implementations or reviewed production harnesses published or materially revised after 2026-09-24 test at least three interface states per workload and expose a separate compatibility delta or blocking threshold.

Established evidence is narrower. [MCPEvol-Bench](https://arxiv.org/abs/2607.14642) measures historical MCP interface evolution and material task-fulfillment degradation. The official [MCP conformance suite](https://github.com/modelcontextprotocol/conformance) freezes requirements by protocol revision. [MCPMark Verified](https://github.com/eval-sys/mcpmark/pull/264) pins server and evaluator versions and deprecates comparison with older task versions. These sources motivate the prediction; they do not prove future adoption. No prior forecast horizon expired today.
