# RuVnet harness improvement — 2026-09-15

## Decision

Accepted exact project and change-kind filters and published RuVnet entry point 0.3.0. `ruvnet changes`, `ruvnet_changes`, and the portable start skill can now narrow reviewed provenance without semantic inference. Filters are allow-listed from the reviewed snapshot, intersected, counted before limiting, and rejected on unknown or extra values. The companion remains offline, read only, and incapable of refreshing or learning by itself.

## MetaHarness loop and measurements

The frozen hypothesis was that exact structured filters would improve relevant provenance retrieval without expanding authority. Baseline `d38753c88aaab3fd958b2dc9802f3b858fb94cb0` passed 0/6 held-out checks; the candidate passed 6/6. Ten test groups, both marketplace schemas, all four portable skills, the MCP SDK subprocess/in-memory paths, package closure, and negative boundaries passed. MetaHarness 0.4.16 remained at 6/6 hard constraints; its readiness score did not change and is not used as proof of improvement.

Fifteen alternating baseline/candidate pairs used 10,000 discovery calls and 20 cold CLI starts per run. Median discovery p95 moved from 0.001332 ms to 0.001222 ms, cold CLI p95 from 71.533 ms to 71.211 ms, and RSS from 47,640,576 to 47,747,072 bytes. All frozen regression gates passed; sub-microsecond timing differences are noise, not a speed claim. Raw results are in [2026-09-15-benchmarks.json](2026-09-15-benchmarks.json).

The pinned Ruflo 3.25.6 deep code and dependency scans, npm audit, and manual tracked-file credential pattern check reported zero known findings. The secret scanner reported only five files and STRIDE only four, so coverage is limited and this is not a claim of complete security. Residual risks are stale reviewed data, upstream claims that were not locally reproduced, host treatment of advisory MCP annotations, and positional CLI ambiguity.

## RuVector, WASM and GNN decision

At pinned RuVector `edaffffb3b85768eb1f3ec1f683b7f46f0506af4`, supported surfaces include durable `VectorDB` search with metadata filters, `@ruvector/wasm` with an adapter-side metadata store, and `ruvector-gnn-rerank`. The same documentation states that WASM HNSW is not active, raw WASM metadata does not round-trip, and GNN reranking is not automatically wired into `VectorDB::search`. Its clustered synthetic GNN benchmark reports +10.4 percentage points over a noisy first stage, but exact L2 is the quality ceiling and much faster in that benchmark.

This run has 10 catalog projects plus 17 reviewed changes: 27 eligible public records, below the frozen 100-record minimum. Persistent vector memory, WASM acceleration, GNN training and persistent learning were therefore not implemented or claimed. The next eligible experiment must compare exact filters, vector-only retrieval, fused retrieval, GNN reranking and a shuffled-graph control on held-out tasks.

## Forecast

Prediction, 80% confidence by 2026-11-14: agent change ledgers and capability catalogs will increasingly expose server-side structured filters or stable pagination so hosts can retrieve provenance with deterministic cache keys. It passes only if at least two primary agent-memory, MCP or tool-registry implementations newly expose such public interfaces. Motivation comes from [vstash's measured hybrid retrieval and adaptive fusion](https://arxiv.org/abs/2604.15484), the [2026-07-28 MCP specification](https://blog.modelcontextprotocol.io/posts/2026-07-28/), and Ruflo's rapidly growing evaluated change set. No previous forecast horizon expired today.

Next hypothesis: add deterministic stable pagination only after the reviewed feed exceeds 20 records and a frozen held-out host task demonstrates that it prevents missed evidence without increasing stale-cache errors.
