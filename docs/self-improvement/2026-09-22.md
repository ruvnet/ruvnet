# RuVnet harness improvement — 2026-09-22

## Decision

Accepted named-option parity for the reviewed change feed as RuVnet entry point 0.10.0. `ruvnet changes` now accepts `--project`, `--kind`, `--cursor` and `--snapshot-id` while preserving the legacy positional interface. Duplicate, mixed, missing, unknown, control-character and authority-expanding arguments fail closed. The companion remains offline, read only and unable to refresh, execute or learn by itself.

No accepted-but-unintegrated candidate was found: every prior accepted entrypoint candidate is an ancestor of the frozen `main` baseline. Independent review accepted this candidate and found no authority expansion.

## MetaHarness loop and measurements

The [frozen plan](2026-09-22-plan.json) defined the hypothesis, six held-out checks and fixed gates before implementation. Baseline `cb3b080` passed 1/6 checks because its CLI could not express named or kind-only change views; the candidate passed 6/6. It matched independent core oracles, preserved byte-equivalent combined legacy output, traversed snapshot-bound pages without duplication, rejected changed-filter cursors and invalid input, and matched MCP evidence views.

All 16 test groups passed on Node 22 and 24. Both marketplace schemas, four skills, six MCP tools and three resources validated. MetaHarness 0.4.16 retained 6/6 hard constraints; its heuristic score is not proof of improvement.

Fifteen alternating pairs used 10,000 filtered change calls and 20 cold CLI starts per arm per pair. Median hot-search p95 rose from 0.001292 ms to 0.001302 ms (+0.77%, +0.000010 ms). Cold CLI p95 rose from 66.909618 ms to 67.797221 ms (+1.33%, +0.887603 ms), and RSS decreased 131,072 bytes. All frozen gates passed. These local microtimings are not end-user performance claims; [raw samples](2026-09-22-benchmarks.json) preserve every run.

The package is 30,097 compressed bytes across 18 files and its normalized dependency closure is unchanged. Pinned Ruflo 3.25.6 deep code and dependency scans and npm audit reported zero known findings. The bundled secret scanner covered five files and STRIDE scan four, so coverage is limited. Cursor hashes are consistency bindings, not authentication. This is not a claim of complete security.

## RuVector, WASM and GNN decision

The sanitized corpus is 11 catalog projects plus 48 reviewed changes: 59 records, below the frozen 100-record gate. Exact retrieval remains the implemented baseline. Product RuVector retrieval, WASM acceleration, GNN training and persistent autonomous learning remain unimplemented and unclaimed. The local coordination memory stored and retrieved one sanitized 384-dimensional pattern for run continuity; that is orchestration evidence, not a shipped harness capability or proof of learning value.

Future evaluation remains exact versus vector-only, fusion, GNN reranking and shuffled-graph control, requiring at least a ten-point held-out task-success gain plus relevance, p50/p95 latency, cold start, memory, artifact size, fixed seeds and reproducibility evidence.

## Forecast

Prediction, 82% confidence by 2026-12-21: agent-harness promotion reports will increasingly require independent repeated-run reliability—strict all-runs success or a bounded flake rate—alongside single-run success for stateful MCP workflows. It passes only if at least two new primary benchmark implementations or reviewed production harnesses published after 2026-09-22 report at least four isolated independent runs per task and use all-run success or a bounded-flake threshold as a promotion gate.

Established evidence is narrower. [MCPMark](https://arxiv.org/abs/2509.24002) evaluates reset stateful MCP sandboxes across four runs and reports a substantial gap between single-run and all-four success. [ReliabilityBench](https://arxiv.org/abs/2601.06112) measures repeated executions and perturbations across 1,280 episodes. [Beyond Pass@k](https://arxiv.org/abs/2608.14711) analyzes independent rollouts and metric inflation. These sources motivate the prediction; they do not prove future adoption. No prior forecast horizon expired today.

Next hypothesis: add an explicitly bounded repeated-run reliability receipt for the stateful MCP surface before considering semantic memory; keep the 100-record vector/GNN gate.
