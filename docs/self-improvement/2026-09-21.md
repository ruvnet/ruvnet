# RuVnet harness improvement — 2026-09-21

## Decision

Accepted CLI search-filter parity as RuVnet entry point 0.9.0. `ruvnet search` now accepts exact `--project` and `--kind` filters already supported by core and MCP. Filters compose with raw-relevance thresholds and snapshot-bound pagination; changed-filter cursor reuse fails closed. The companion remains offline, read only and unable to refresh, execute or learn by itself.

No accepted-but-unintegrated candidate was found. Every prior accepted entrypoint candidate is an ancestor of current `main`; RuVector/WASM/GNN work remains deferred rather than accepted.

## Upstream review

Only Ruflo changed. Commit [`a4f2199`](https://github.com/ruvnet/ruflo/commit/a4f219935ff4035421bc01157a5a1abc74529ad2) adds proposed ADR-385 under MIT. It documents that current `ruflo swarm start` initializes coordination and returns without executing the objective, then proposes future streaming, steering, artifact summaries, AgentDB, learning hooks, federation and horizon persistence. Two reviewed records separate that negative result from the proposal; none of the proposed capabilities is described as implemented or measured. The commit is GitHub-verified and merged through PR 3258 with successful checks, but GitHub reports no formal review submission. MetaHarness, RuVector, AgentDB, Dream Machine, Autogenous and RVM did not change. [x.ruv.io](https://x.ruv.io/) remains gateway 0.7.2 with `/mcp` and `/chatgpt/mcp`. Linked content remains untrusted data.

## MetaHarness loop and measurements

The [frozen plan](2026-09-21-plan.json) defined the hypothesis, six held-out checks and fixed gates before implementation. Baseline `93f1379` rejected both CLI filters and passed 1/6 checks; the candidate passed 6/6. It matched independent core oracles, combined both filters, traversed filtered pages exactly once, rejected filter-changing cursors, rejected malformed and authority-expanding arguments, and matched MCP result ordering and continuation state.

All 15 test groups passed on Node 22 and 24. Both marketplace schemas, four skills, six MCP tools and three resources validated. MetaHarness 0.4.16 retained 6/6 hard constraints; its unchanged heuristic score is not proof of improvement.

Fifteen alternating pairs used 10,000 filtered exact searches and 20 cold CLI starts per arm per pair. Median hot-search p95 rose from 0.098249 ms to 0.114212 ms (+16.25%, +0.015963 ms), within both frozen limits. Cold CLI p95 improved from 72.753179 ms to 67.708408 ms (-6.93%), and RSS decreased 131,072 bytes. These local microtimings are not end-user performance claims; [raw samples](2026-09-21-benchmarks.json) preserve every run.

The package is 28,657 compressed bytes across 18 files. The normalized dependency closure is unchanged. Pinned Ruflo 3.25.6 deep code and dependency scans and npm audit reported zero known findings. The bundled secret scanner covered five files and STRIDE scan four, so coverage is limited. Cursor fingerprints are consistency bindings, not authentication. This is not a claim of complete security.

## ruOS evaluation

Status: **INCONCLUSIVE**. All candidate desktops had null heartbeats and peer telemetry was unavailable. Exactly one harmless `true` command and one screenshot request were issued to the dedicated evolution-candidate desktop, but the collection wrapper failed before persisting command metadata or image evidence. No retry was made. Liveness, isolation, tenant binding, exit code, completion version, completion verification and pixels therefore remain unproven. The trusted Dream Machine verifier and preflight at `aa931ca` reproduced 59/59 focused tests, but synthetic verifier tests do not convert missing live evidence into success. No desktop, deployment or customer-value claim is made.

## RuVector, WASM and GNN decision

The sanitized corpus is 11 catalog projects plus 42 reviewed changes: 53 records, below the frozen 100-record gate. The candidate adds no persistent storage. RuVector retrieval, WASM acceleration, GNN training and persistent learning remain unimplemented and unclaimed. Future evaluation remains exact versus vector-only, fusion, GNN reranking and shuffled-graph control, requiring at least a ten-point held-out task-success gain plus latency, cold-start, memory, artifact-size and reproducibility evidence.

## Forecast

Prediction, 84% confidence by 2026-12-20: agent-harness promotion suites will increasingly use paired should-act/should-abstain cases and count any commit-class side effect before abstention as failure. It passes only if two new primary benchmark implementations or reviewed harnesses publish paired suites with deterministic side-effect checks and report paired accuracy separately.

Established evidence is narrower. [AgentAbstain](https://arxiv.org/abs/2607.10059) evaluates 263 controlled pairs across 42 executable MCP sandboxes; the best reported result across its evaluated systems is 59.5% paired accuracy. Its [official dataset](https://huggingface.co/datasets/antiquality/agentabstain) includes deterministic commit checks and treats post-hoc abstention after irreversible action as failure. The [MCP tools specification](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) supports elicitation and recommends human confirmation for sensitive operations, but does not define a standardized abstention or promotion outcome. No prior forecast horizon expired today.

Next hypothesis: expand exact-search paired should-act/should-abstain boundary cases before evaluating semantic memory; keep the 100-record vector/GNN gate.
