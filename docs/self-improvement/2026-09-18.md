# RuVnet harness improvement — 2026-09-18

## Decision

Accepted explainable exact-token search for reviewed upstream evidence as RuVnet entry point 0.6.0, pending publication and CI. `ruvnet search` and `ruvnet_search_changes` return exact matched terms and `rawRelevance`, defined only as the matched unique query-term fraction. They do not claim semantic similarity, ranking confidence, embeddings or learning. The companion remains offline, read only and unable to refresh or learn by itself.

## Upstream review

Ruflo advanced to [3.42.4](https://github.com/ruvnet/ruflo/releases/tag/v3.42.4) at `e558f0c0fc29c1a658085f6e6f80ad27d4fe811f`. Two reviewed records were incorporated: the release and commit [`702d146`](https://github.com/ruvnet/ruflo/commit/702d146178214aab4ad41d00ac8b47767dbd6649), which separates raw SmartRetrieval relevance from downstream RRF ranking score and preserves pre-ranking threshold semantics. The release explicitly leaves the reasoning-bank/vector-backend bridge fallback unresolved, so no corresponding capability is claimed. MetaHarness, RuVector, AgentDB, Dream Machine, Autogenous and RVM were unchanged. x.ruv.io still reports version 0.7.2 with `/mcp` and `/chatgpt/mcp` routes.

## MetaHarness loop and measurements

The [frozen plan](2026-09-18-plan.json) defined the hypothesis, six held-out checks and regression gates before implementation. Baseline `7965670321cce42b7db65138c0a8f40ddb5d584c` passed 0/6; the candidate passed 6/6. All 12 test groups passed on Node 22 and 24, along with both marketplace schemas, four portable skills, MCP SDK subprocess and in-memory paths, package closure and negative boundaries. MetaHarness 0.4.16 remained at 6/6 hard constraints; its unchanged heuristic score is not evidence of the task improvement.

Fifteen alternating pairs used 10,000 discovery calls and 20 cold CLI starts per run. Median discovery p95 moved from 0.001272 ms to 0.001382 ms (+8.65%), cold CLI p95 from 68.912 ms to 70.007 ms (+1.59%, +1.095 ms), and RSS rose 262,144 bytes. All frozen gates passed. These local microtimings are not product-speed claims; [raw samples](2026-09-18-benchmarks.json) preserve every run.

Pinned Ruflo 3.25.6 deep code and dependency scans, npm audit and a tracked-file credential-pattern check reported zero known findings. Its secret scanner covered five files and STRIDE four, so coverage is limited. Trust boundaries now include untrusted query text, exact filters, reviewed JSON, host interpretation of `rawRelevance`, and linked evidence. Residual risks include missed synonyms, stale evidence and score overinterpretation. This is not a claim of complete security.

## RuVector, WASM and GNN decision

The corpus now contains 10 catalog projects plus 38 reviewed changes: 48 sanitized public records, below the frozen 100-record gate. Exact-token retrieval is implemented and measured with no persistent storage. RuVector retrieval, WASM acceleration, GNN training and persistent learning remain unimplemented and unclaimed. The future evaluation remains exact versus vector-only, fusion, GNN reranking and shuffled-graph control, requiring at least a ten-point held-out task-success gain plus latency, cold-start, memory, artifact-size and reproducibility evidence.

## Forecast

Prediction, 84% confidence by 2026-12-17: agent-memory retrieval interfaces will increasingly distinguish raw retrieval relevance from downstream ranking or confidence and expose enough match provenance to audit threshold behavior. It passes only if at least two primary implementations or interoperability specifications newly publish separate raw-relevance and ranking/confidence fields plus regression tests or threshold semantics.

Established signals are narrower. Ruflo 3.42.4 corrects one score-contract bug. [MemX](https://arxiv.org/abs/2603.16171) publishes a reproducible local-first hybrid retrieval baseline with RRF and measured query suites. [MemReranker](https://arxiv.org/abs/2605.06132) identifies relevance-score miscalibration and reports measured reranking tradeoffs. The forecast extrapolates beyond those results. No prior forecast horizon expired today.

Next hypothesis: add field-weighted exact retrieval only if a frozen ablation improves held-out provenance task success without obscuring score semantics; otherwise retain the simpler overlap baseline.
