# RuVnet harness improvement — 2026-09-17

## Decision

Accepted a content-addressed snapshot contract and published RuVnet entry point 0.5.0. Every reviewed-change page now exposes a deterministic SHA-256 identifier. CLI and MCP callers can send that identifier with a continuation cursor; a changed snapshot fails closed before returning records, preventing pages from different evidence states from being mixed. The digest is a consistency check, not a signature, publisher identity or authorization token. The companion remains offline, read only and unable to refresh or learn by itself.

## RuVector, WASM and GNN decision

At pinned RuVector `b336fbae8b15a5a487fc3e7c14a80dcb4984b04a`, the reviewed surfaces include flat/HNSW `VectorDB`, `@ruvector/wasm`, a GNN reranking research surface, and an optional `@ruvector/mincut-wasm` wrapper with exact TypeScript fallback, dynamic cut and directed routing. The new MinCut work is a graph-topology capability, not evidence that vector retrieval or GNN learning improves this entry point.

This run has 10 catalog projects plus 36 reviewed changes: 46 sanitized public records, below the frozen 100-record gate. Exact filtering, snapshot-bound paging and a deterministic digest remain the baseline. Persistent vector memory, WASM acceleration, GNN training and persistent learning were not implemented or claimed. Artifact size and latency were not measured because the candidate rejected those dependencies before adoption. The future experiment remains exact filters versus vector-only, fusion, GNN reranking and a shuffled-graph control, requiring a 10-point held-out task-success gain.

## Forecast

Prediction, 82% confidence by 2026-12-16: agent evidence and memory interfaces will increasingly expose content-addressed snapshot or receipt identifiers so caching, replay and audit can fail closed across state transitions. It passes only if at least two primary implementations newly publish digest-, receipt- or revision-bound metadata used for cache invalidation or replay verification.

Established signals are narrower. [MCP caching guidance](https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/caching) defines cache validation semantics. [NovaFabric](https://arxiv.org/abs/2609.12582) reports signed run capsules and tamper rejection, but only 2/10 tool-using workloads completed. [MutMem](https://arxiv.org/abs/2608.02843) reports signed mutation transitions while explicitly not establishing content truth, and [MemMark](https://arxiv.org/abs/2605.25002) studies attribution surviving memory snapshots. The forecast goes beyond those established results. No previous forecast horizon expired today.

Next hypothesis: add a verifiable publisher receipt only if a stable trust root and independent verification path can be pinned; an unsigned digest must not be relabeled as authenticity.
