# RuVnet harness improvement — 2026-09-20

## Decision

Accepted snapshot-bound pagination for reviewed exact-token search as RuVnet entry point 0.8.0, pending publication and CI. A `nextCursor` is bound to the content snapshot, canonical query tokens, exact filters, raw-relevance threshold and offset. CLI and MCP callers must continue with the returned cursor and `snapshotId`; malformed, stale or cross-query reuse fails closed. The companion remains offline, read only and unable to refresh, execute or learn by itself.

No accepted-but-unintegrated candidate was found. Every prior accepted entrypoint candidate is an ancestor of current `main` and CI-verified; RuVector/WASM/GNN work remains deferred rather than accepted.

On baseline `a7375c617f705c4ac0bb74726f32272beaa5a12f`, a full-overlap `ruflo` search reported 25 matches but made only 20 reachable. Baseline passed 1/6 held-out checks; the candidate passed 6/6 and traversed all matches exactly once. Median hot-search p95 rose from 0.126606 ms to 0.143341 ms (+13.22%, +0.016735 ms), cold CLI p95 from 62.098634 ms to 62.553980 ms (+0.73%, +0.455346 ms), and RSS by 737,280 bytes. All frozen gates passed. These local microtimings are not end-user performance claims; [raw samples](2026-09-20-benchmarks.json) preserve every run.

The compressed package is 27,939 bytes across 18 files. The lockfile's root package version changed from 0.7.0 to 0.8.0, while its resolved dependency closure remained byte-identical after normalization. Pinned Ruflo 3.25.6 deep code and dependency scans and npm audit reported zero known findings. The bundled secret scanner covered five files and STRIDE scan four, so coverage is limited. Cursor fingerprints are consistency bindings, not authentication or deliberate-tamper resistance. This is not a claim of complete security.

## RuVector, WASM and GNN decision

The sanitized corpus is now 11 catalog projects plus 40 reviewed changes: 51 records, below the frozen 100-record gate. The candidate adds no persistent storage. RuVector retrieval, WASM acceleration, GNN training and persistent learning remain unimplemented and unclaimed. The future evaluation remains exact versus vector-only, fusion, GNN reranking and shuffled-graph control, requiring at least a ten-point held-out task-success gain plus latency, cold-start, memory, artifact-size and reproducibility evidence.

## Forecast

Prediction, 87% confidence by 2026-12-19: desktop-agent evaluation will increasingly require both authoritative post-execution state and visual evidence, treating missing or mismatched evidence as `INCONCLUSIVE` rather than `PASS`. It passes only if two new primary benchmark implementations or reviewed interoperability contracts require both channels.

Established signals are narrower. [Interactive Reward Agent](https://arxiv.org/abs/2607.25904) reports that screenshots alone are insufficient and evaluates GUI plus environment state. [MobileWorldSafety](https://arxiv.org/abs/2608.17659) uses programmatically verifiable final-state indicators. [DuMateBench](https://arxiv.org/abs/2608.26546) evaluates stateful tasks in isolated, perturbed containers. MCP `complete` is protocol completion, not independently verified task success. No prior forecast horizon expired today.

Next hypothesis: evaluate cursor expiry or signed receipts only after a measured stale-client failure; do not add authentication complexity without a concrete threat and held-out benefit.
