# RuVnet harness improvement — 2026-09-19

## Decision

Accepted an optional minimum raw-relevance gate for reviewed-change search as RuVnet entry point 0.7.0, pending publication and CI. CLI callers use `--min-raw-relevance`; MCP callers use `minRawRelevance`. The value is bounded from 0 to 1 and filters the already exposed exact-token overlap before limiting. Omission defaults to zero and preserves 0.6.0 behavior. It is not semantic similarity, ranking confidence, answer confidence or value of information. The companion remains offline, read only and unable to refresh or learn by itself.

## MetaHarness loop and measurements

The [frozen plan](2026-09-19-plan.json) defined the hypothesis, six held-out checks and regression gates before implementation. Baseline `015725be93fadb3484474cae218cdc51dba2372b` passed 3/6; the candidate passed 6/6. With a full-overlap gate, `raw retrieval ranking` narrowed from three lexical matches to the intended Ruflo score-semantics record. All 13 test groups passed on Node 22 and 24, along with both marketplace schemas, four portable skills, MCP SDK subprocess and in-memory paths, package closure and negative boundaries. MetaHarness 0.4.16 remained at 6/6 hard constraints; its unchanged heuristic score is not evidence of the task improvement.

Fifteen alternating pairs used 10,000 discovery calls and 20 cold CLI starts per run. Median discovery p95 moved from 0.001001 ms to 0.000972 ms (-2.90%), cold CLI p95 from 72.640 ms to 71.850 ms (-1.09%, -0.790 ms), and RSS fell 118,784 bytes. All frozen gates passed. These local microtimings are not product-speed claims; [raw samples](2026-09-19-benchmarks.json) preserve every run.

Pinned Ruflo 3.25.6 deep code and dependency scans, npm audit and a tracked-file credential-pattern check reported zero known findings. Its secret scanner covered five files and STRIDE four, so coverage is limited. The new numeric input is checked by both MCP schema and runtime validation for finite values from 0 to 1. Residual risks include lexical recall loss and hosts overinterpreting the score despite explicit labels. This is not a claim of complete security.

## RuVector, WASM and GNN decision

The corpus remains at 10 catalog projects plus 38 reviewed changes: 48 sanitized public records, below the frozen 100-record gate. The candidate adds no persistent storage. RuVector retrieval, WASM acceleration, GNN training and persistent learning remain unimplemented and unclaimed. The future evaluation remains exact versus vector-only, fusion, GNN reranking and shuffled-graph control, requiring at least a ten-point held-out task-success gain plus latency, cold-start, memory, artifact-size and reproducibility evidence.

## Forecast

Prediction, 82% confidence by 2026-11-18: agent-memory retrieval interfaces will increasingly expose a configurable retrieval-relevance gate explicitly separate from answer confidence, downstream ranking and value-of-information decisions. It passes only if at least two primary implementations or interoperability specifications newly document such separate controls.

Established signals are narrower. Ruflo 3.42.4 preserves thresholding over raw relevance before downstream ranking. [Matched Trajectory Replay](https://arxiv.org/abs/2608.26846) reports that confidence calibration can improve risk-coverage tradeoffs but does not estimate the benefit of another retrieval. [MemReranker](https://arxiv.org/abs/2605.06132) identifies score miscalibration as a barrier to threshold filtering. The forecast extrapolates beyond those results. No prior forecast horizon expired today.

Next hypothesis: add a stable, snapshot-bound search cursor only if the reviewed corpus grows enough for thresholded results to exceed one page; until then a cursor would add complexity without demonstrated task benefit.
